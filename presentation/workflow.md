# AI Native 的硬件乘法架构

## 硬件 = 电路 × 软件 × 机械设计

电路 = Agent(需求，电气约束)\
软件 = Agent(需求，行为约束)\
机械设计 = Agent(需求，结构约束)

Agent 生成结果，评估函数计算偏差，反馈驱动迭代。

PAO：用一台小车，探索一套可复用的开发流程。

<!--
这是我们对硬件开发的架构表达，不是物理定律。任意硬件项目都可以从电路、软件、机械设计三个维度展开，但组合能否成立仍取决于接口、电源、尺寸、负载和验收约束。
-->

---

# 结果交给评估，偏差驱动迭代

## 结果 = Agent(需求，约束)

## 偏差 = Evaluate(结果，验收目标)

偏差 < 既定阈值 → 交付

否则 → 将偏差反馈给 Agent，继续修复与评估。

# 能用手机解决，就用手机

- 语音、屏幕、联网：先考虑二手手机。
- 移动、驱动、定制结构：再引入专用硬件。

硬件的价值，来自必须进入物理世界的需求。

<!--
手机通常已集成计算、通信、传感和交互能力，应先作为实现方案比较，而不是为硬件而硬件。这里不对其他团队的性能、成本或稳定性作未经测量的排名。小车和鸭子是讨论中提到的实体载体，是否需要专用硬件仍由具体需求决定。
-->

# 三个维度，分别建设、按约束组合

- 电路：器件、供电、接口与连接。
- 软件：驱动、控制逻辑与业务应用。
- 机械设计：形状、装配、运动与负载。

以正交分解降低耦合，以接口约束保证协同。

<div class="bottom-note">许式伟将“正交分解”列为架构设计准则。<a href="https://time.geekbang.org/column/article/167844">《如何判断架构设计的优劣？》</a></div>

<!--
三个维度适合分别表达和演进，但物理实现不是完全独立：电机负载影响电源，器件封装影响结构，时序与资源影响软件。正交是降低耦合的设计方向，接口和验收负责管理这些交叉约束。
-->

# 从功能相加，到能力相乘

## 单个产品：功能 A + 功能 B + 功能 C

## 开发流程：电路能力 × 软件能力 × 机械能力

完成议题要求后，把投入放在可复用的工作流上。

<!--
应用功能本身有价值，也容易被复刻。我们的探索是提高抽象层级，让新的需求能复用已有工程能力。乘法架构不排斥新增功能；关键在于新增工作是否留下可复用的模块、接口和验收。
-->

# 从软件工程，走向硬件开发

Claude Code 让大家看到，AI 可以直接进入软件工程，\
运行工具、读取测试结果，再继续修改。

我们探索的是同样的工作方式在硬件开发中如何成立。

---

# AI Native：工程就是 Agent 的工作空间

- 代码描述电路、软件与机械结构。
- 工具构建工程，仿真运行设计。
- 评估返回证据，Agent 据此修复。

## 需求 → 生成 → 构建 → 评估 → 修复

<!--
AI Native 体现于工程组织方式：Agent 能修改输入，调用工具，读取真实失败结果，再继续迭代。当前电子工程流程已在内置模块与接口范围内支持有上限的自动修复；机械建模与仿真仍在研发，统一全流程自动化是目标。人工负责需求、验收标准与实物确认。
-->

# 超声波：用一次加法，检验乘法

- 加入一个新模块。
- 检查接线、驱动、仿真与行为验收。
- 观察 Agent 能否沿同一流程完成扩展。

新增测距能力，是工作流的验证题。

<!--
超声波确实为小车增加了功能，目的却是检验流程能否迁移到新模块。仅凭模块接入或一次演示，不能宣称 Agent 已全自动完成任意硬件开发；应保留各环节的工程与验收证据。
-->

---

# 做减法：摄像头没有加

满足议题约束后，停止继续堆叠功能。

把精力留给电路、软件、机械设计的可组合性。

> 少，就是指数级的多

<div class="bottom-note">许式伟反复引用的 Go 团队理念。<a href="https://news.qiniu.com/archives/1765424929537">《XGo 全景图》</a>，2025-07-29。</div>

<!--
摄像头是讨论过但没有加入的功能。减法不是少做必要的验证，而是减少与本次工作流探索无关的功能。这里引用的理念不是许式伟首创。
-->

# 应用可以变，开发流程可以复用

## 电路 × 软件 × 机械设计

- 小车：运动控制与执行机构。
- L-play、狼人杀：不同的软件应用方向。

让 Agent 在约束内探索新的组合。

<!--
L-play 与狼人杀来自讨论，是潜在应用方向，不表示仓库已经实现相应协议或应用，也不表示这些应用必须使用专用硬件。能用手机完成的部分仍优先用手机；平台的价值是支撑确有物理交互需求的组合。
-->
