# 固件协作规范

本文件适用于 `firmware/` 下的代码、板型和构建脚本，并补充仓库根目录的协作规范。

## 测试与验证

- 当前阶段默认不新增测试代码、Mock、测试专用脚本或 CI 测试任务；用户明确要求测试时再引入。
- 不手写整套 ESP-IDF 替身：避免复制 SDK 的类型、头文件和函数声明，或自行模拟 GPIO、PWM 等外设的状态机。
- 后续需要测试时，优先使用 ESP-IDF 的 Unity、CMock 和 pytest-embedded，先确认所需组件及运行环境的支持范围，保持测试规模与项目逻辑相称。
- 按改动范围运行已有的静态检查、编译和相关测试。仅修改文档时检查内容及差异，无需构建固件。
- 如实区分静态检查、编译通过、模拟测试和实机验证。未连接硬件或未实际执行的检查应明确说明；编译或 Mock 测试通过不能证明真实 GPIO/PWM 时序及带载行为正确。
