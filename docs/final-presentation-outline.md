# PAO 决赛答辩大纲

面向 2026 1024 Hackathon 智能硬件赛道，按 10 分钟展示设计：讲述约 9 分 15 秒，预留约 45 秒给切换和现场停顿。核心叙事是：**构建 Agent 时代的硬件开发新流程：代码让 Agent 能动手，评估函数让 Agent 知道是否做对，模拟器让评估可自动执行。**

可运行的演示稿见根目录 [presentation/](../presentation/README.md)。

观众应记住三件事：电路设计、固件编写和固件运行都由代码驱动；评估函数把连通性、规则与运行行为转成明确的通过条件和错误；透明芯片级仿真让正式固件无实物运行，自动评估结果再反馈给 Agent 修复。PAO Studio 已在内置器件和接口模型范围内实现这条本地实验链路，PAO 小车则用于验证模块、固件与实物行为之间的对应关系。未来计划把闭环扩展到机械结构与刚体动力学评估，并将全流程封装为可复用的 Skill。

## 讲述口径

开场可说：“我们正在构建 Agent 时代的硬件开发新流程。电路设计是代码，固件是代码，连固件的运行环境也是代码。代码让 Agent 能动手，评估函数让 Agent 知道是否做对，模拟器让评估可自动执行。PAO Studio 把这条路径变成开发工具，PAO 是对应的验证产品。”

收尾可说：“下一步，我们计划把自动开发闭环扩展到整机：让 Agent 生成机械结构，用刚体动力学的轨迹、碰撞和稳定性结果作为评估函数，让 AI 自动验收并修复，再把电路、固件、结构的完整流程封装成 Skill。今天已跑通的是支持模块范围内的电子工程与固件闭环；整机物理评估是接下来要实现的方向。”

“评估函数”是可执行的规则和断言。PAO 参考电路测试会比对编译后网络的全部成员，缺线或额外短接都会失败；Studio 在自动开发过程中执行电气、PCB、编译和运行评估。电路短接检查依据网络关系和铜几何规则，不计算模拟短路电流。软件在环会核对 UART 业务状态、实际 I²S PCM 幅度及频率、电机桥臂占空比与暂停归零；OLED 当前检查显存是否到达，不逐像素判断画面。首份有效验收场景由模型提出，并在修复中固定；仍需核对场景是否充分表达人的需求。

“全自动”指已支持模块范围内的选型、工程生成、编译、仿真验收和有限轮次修复；需求与验收目标仍需人确认，平台不自动刷写实物或下单生产。根目录 `hardware/` 的 TSX 是 PAO 参考接线图；Studio 生成的是模块安装载板，不表示重新设计了采购模块的内部电路。

“对固件透明”指正式应用与驱动沿用原有执行路径，不需要模拟器专用业务分支。主要固件链路可以无实物运行，覆盖范围取决于已有芯片和外设模型，当前没有“绝大部分代码”的覆盖率统计。软件在环不验证温升、射频、声学、机械负载或传感器实际精度。

机械结构生成、刚体动力学评估和全流程 Skill 均为未来规划。当前 PAO 运动位姿按两轮 PWM 与简化运动关系计算，尚未接入刚体动力学物理引擎。未来自动验收依据预先确定的场景、指标和阈值执行，仿真通过仍需通过实物对照确认模型及实际表现。

PAO 参考机和 Studio 自由组合板型分别维护。实车演示不能作为任意组合已通过实物验收的证据，也不能据此宣称 PAO 整车由 Studio 一键生成。整机闭环、批量回归、硬件在环和实物对照的推进目标见[平台规划](platform-roadmap.md)。

## 演示准备

- 第 2 页准备真实源码入口；第 3 页准备连通性断言和运行评估函数；第 4 页准备一条具体的编译或运行失败反馈，说明修复如何保持原验收标准。第 5 页准备正式固件的构建与运行入口，方便解释固件如何进入芯片模型。
- 第 6 页准备模拟器页面、固件日志与[演示视频](../simulator/README.md#页面)。现场语音需要设备激活和麦克风授权；若未具备条件，使用已有演示素材。
- 第 7 页使用一个预先完成并核验的 Studio 案例，保留同一工程的原理图、PCB、DRC、Gerber / CAM、固件编译与软件在环结果，分别展示。图片用于说明界面，验收结论以对应工程记录为准。
- 第 8 页的实车演示选择可立即停车的短程动作，确保观众看到车体与反馈；备用为已有[实车视频](making-of.md#演示视频)。技术参数、完整接线和未展开的功能留到答辩追问。

功能、验证方式及素材入口分别见[项目首页](../README.md)、[制作过程](making-of.md)、[模拟器说明](../simulator/README.md)和[Studio 说明](../experimental/platform/README.md)。
